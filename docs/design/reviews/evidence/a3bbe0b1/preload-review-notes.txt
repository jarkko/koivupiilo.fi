   Mechanism: the 3 preloaded files (123 KiB) start downloading alongside the 38 KiB stylesheet and
   share the throttled bandwidth with it. The stylesheet finishes about 2.9x later (359 -> 1052 ms), and
   first paint waits for the stylesheet. The fonts don't arrive any sooner (1123 vs 1146 ms). With
   preload, the first paint simply waits until the fonts are ready, so on the 1.6 Mbps profile the font
   swap and its shift disappear. At 400 kbit/s the fonts still arrive after the CSS, so the shift stays
   and first paint is 2.4 s later. Lighthouse's simulated mode models the request graph differently and
   reports an improvement. Its observed devtools mode agrees with the raw probe.

   Limits: the local server is Python http.server (HTTP/1.1, no prioritisation), and Chrome's devtools
   throttling shares bandwidth evenly between requests. Production is GitHub Pages over HTTP/2. If the
   CDN sends the Highest-priority stylesheet before the High-priority font preloads, the stylesheet
   delay could be much smaller in production. Production was unreachable from the sandbox, so this is
   not verified.
